# Финальная проверка Томирис

## Подготовлено

- Расчёт Score, контрольные числа, бюджет и несовместимости проверены тестами.
- Проверка части Айсаны: лаги всех 14 мер, три синергии, городские эффекты, неизменность данных и все 120 перестановок контрольного набора.
- AI получает уже рассчитанные данные, бюджет и вклады мер. Числовые факты в объяснение подставляет код.
- Три варианта модели: GPT-4o mini, GPT-4.1 mini, GPT-4.1. Выбор сохраняет расчёт, прежний текст сбрасывается.
- Ошибки ключа, сети, формата ответа и чтения `.env` обрабатываются без потери результата.
- 104 теста прошли; новая AI-интеграция проверена с подменёнными ответами API. На компьютере команды API уже вернул ответ; он был отклонён прежним фильтром. Фильтр исправлен, повторное живое объяснение ещё нужно проверить.
- README, отчёт по ТЗ, слайд и речь находятся в репозитории. `.env.example` удалён; настоящий `.env` остаётся локальным.

## Осталось выполнить на компьютере команды

1. После сохранения своих изменений получить актуальный `main` командой `git pull --ff-only origin main`. Если Git сообщает о конфликте или локальных правках, остановиться и разобраться; не применять принудительный сброс.
2. Остановить старый Streamlit через Ctrl+C. В активированном окружении выполнить `python -m tools.demo --live-ai`. Команда проверит проект, запросит реальное объяснение (до двух API-вызовов при отклонении первого ответа) и запустит интерфейс. Для другого свободного порта добавить `--port 8502`.
3. В браузере повторить контроль: стоимость **95**, Score **56.54**, синергия **M10 + M12 → B1 +2 в Нуре**. Получить подписанный AI-комментарий; отсутствие слова «резервное» подтверждает, что принят ответ API.
4. После редизайна Ардак повторить этот сценарий и проверить, что выбор модели, объяснение и таблицы видны. Изменения дизайна в этой работе не выполнялись.
5. Пройти общий прогон на пять минут по `TOMIRIS_DEFENSE.md`. Открыть `tomiris-slide.pptx` заранее.
6. Проверить последний push и отправить решение через платформу до установленного организаторами срока. Наличие коммита не заменяет отправку решения в форме платформы.

## Как показывать AI на защите

Основной сценарий — с настоящим AI. Резервный режим нужен при недоступности внешнего API: он сохраняет работоспособность и честно обозначает источник текста. Специально демонстрировать его необязательно; коротко показать можно при вопросе жюри о надёжности.

Текст Томирис: «Расчёт выполняется независимо от модели. AI объясняет улучшения, оставшиеся проблемы и компромиссы. Если внешний сервис недоступен, числовой результат остаётся доступным, а приложение явно показывает резервное объяснение».
