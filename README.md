# Аким на 5 часов

AI-симулятор управления городским бюджетом для спецтрека **Astana Innovations** на **HackAlem AI**.

Команда получает данные о пяти районах Астаны и бюджет 100 условных единиц. Пользователь выбирает ровно пять городских инициатив, после чего детерминированный движок рассчитывает изменения показателей и итоговый **Astana Quality of Life Score**. AI получает уже рассчитанный результат и объясняет его понятным языком: что улучшилось, какие проблемы остались и какие компромиссы возникли.

## Зачем нужен проект

Городские решения редко улучшают всё одновременно. Ограниченный бюджет заставляет выбирать между транспортом, экологией, социальной сферой, безопасностью и городскими сервисами.

Симулятор помогает:

- сравнить последствия набора инициатив;
- увидеть изменения по каждому району;
- учитывать сроки реализации и синергии;
- не скрывать слабейший район за хорошим средним значением;
- получить понятное объяснение результата без передачи расчётов языковой модели.

## Как работает симуляция

1. Пользователь выбирает пять разных инициатив.
2. Для районной инициативы указывает район; городская применяется ко всем районам.
3. Валидатор проверяет бюджет, направления, районы, повторы и несовместимые пары.
4. Расчётный движок применяет эффекты с учётом лага и синергий.
5. Для каждого района рассчитывается собственный балл.
6. Итоговый Score учитывает среднее по населению, слабейший район и критические показатели.
7. AI объясняет готовый результат и не выполняет математические расчёты.

## Правила

- Бюджет: не более 100 условных единиц.
- Количество решений: ровно 5.
- Повторять одну инициативу нельзя.
- Не более двух инициатив одного направления.
- Для типа «Район» нужен существующий район.
- Для типа «Город» район не указывается.
- M1 и M3 несовместимы во всём городе.
- M4 и M7, а также M5 и M13 несовместимы только в одном и том же районе.
- Порядок выбранных решений не влияет на результат.

## Расчёт Score

Эффект инициативы за горизонт симуляции:

```text
реализованный эффект = эффект × (8 − лаг) / 8
```

После применения эффектов и синергий показатели ограничиваются диапазоном от 0 до 100.

```text
D_d    = сумма показателей района с весами
D_avg  = средневзвешенный балл районов по населению
N_crit = количество показателей строго ниже 40

Score = 0.7 × D_avg + 0.3 × min(D_d) − N_crit
```

Числа рассчитывает код. AI только интерпретирует переданные значения.

## Данные

В модели используются десять показателей качества жизни:

| Направление | Показатели |
|---|---|
| Транспорт | T1 — разгрузка дорог, T2 — доступность общественного транспорта |
| Экология | E1 — озеленение, E2 — качество воздуха |
| Социальная сфера | S1 — школы и детские сады, S2 — поликлиники |
| Безопасность | B1 — безопасность улиц, B2 — безопасность дорожного движения |
| Городские сервисы | C1 — надёжность ЖКХ, C2 — скорость решения обращений |

Исходные районы, каталог инициатив и правила хранятся в JSON-файлах. Интерфейс и AI-модуль не дублируют цены, веса и эффекты вручную.

## Архитектура

Поток данных:

```text
выбор решений → валидация → эффекты → Score → AI-объяснение
```

## Команда

### Ардак — выбор решений и правила

- валидация игрового набора;
- интерфейс выбора инициатив и районов;
- счётчик бюджета и сообщения об ошибках;
- подготовка структурированного контекста для AI.

### Айсана — эффекты и изменения города

- применение районных и городских эффектов;
- учёт лагов, синергий и границ 0–100;
- отображение показателей до и после;
- промпт и проверка содержательной точности AI-ответа.

### Томирис — итоговый Score и AI-интеграция

- расчёт районных и городского баллов;
- сборка полного расчётного пути;
- панель итогового результата;
- вызов модели, обработка ошибок и резервное объяснение.

Каждая участница работает с логикой, интерфейсом, AI-частью, тестами и участвует в защите проекта.

## Запуск

Требуется Python 3.10 или новее.

```bash
git clone https://github.com/BAITC-Hacks/hack-fa5087f9-turtle.git
cd hack-fa5087f9-turtle

python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Для повторения проверенной среды используйте `pip install -r requirements-tested.txt`.
Проверено на Python 3.14.7; этот файл фиксирует версии трёх основных библиотек.
В Windows активация окружения: `.venv\Scripts\Activate.ps1`.

Для живого AI-объяснения создайте локальный `.env` из примера:

```bash
cp .env.example .env
```

Откройте `.env` и вставьте личный проектный ключ после `OPENAI_API_KEY=`. Файл
`.env` уже исключён из Git: не добавляйте его в коммиты и не отправляйте ключ в чат.
Вместо файла ключ по-прежнему можно задать через переменную окружения.

Без ключа симулятор показывает локальное резервное объяснение из готовых данных движка.
Оно также используется при ошибке API; Score и таблица изменений доступны независимо от AI.

Запуск приложения:

```bash
python -m streamlit run frontend/app.py
```

Откройте адрес, который напечатан в терминале (обычно `http://localhost:8501`).
Оставьте терминал с запущенным приложением открытым. Если браузер пишет
`ERR_CONNECTION_REFUSED`, сначала убедитесь, что команда запуска продолжает работать.

Модель по умолчанию берётся из `OPENAI_MODEL` в `.env`. В интерфейсе можно выбрать
`gpt-4.1` или `gpt-4o-mini` для следующего запроса. GPT‑4.1 — кандидат для более
требовательного следования инструкциям; доступность и задержку проверяйте вашим ключом.
Никакая модель не гарантирует смысловую безошибочность текста.

При первом открытии уже выбран контрольный набор из ТЗ стоимостью 95 у.е.; его можно изменить перед расчётом.

2. Проверьте: стоимость **95**, остаток **5**, Score **56.54**, изменение к базе

3. Нажмите «Получить AI-объяснение». Живой ответ подписан названием модели.
   Стоимость, дельты, лаги и бонус берутся из расчёта; AI добавляет текстовую интерпретацию.
4. Отметьте «Показать работу без AI» и снова запросите объяснение. Будет показан
   подписанный резервный текст. Score и все три таблицы останутся доступны.
   Это демонстрация без запроса к API; таймаут и отсутствие ключа также проверяются автотестами.
5. Снимите отметку для живого AI. Замените последнюю меру M5 на M4 в Сарыарке:
   старый результат исчезнет. Повторите расчёт и убедитесь, что Score изменился.
6. Для превышения бюджета выберите M3/Есиль, M5/Сарыарка, M8/Нура, M12/город,
   M10/Алматы: стоимость **101**, расчёт блокируется с понятной причиной.

## Роль AI и ограничения

AI не определяет стоимость инициатив, не применяет эффекты и не рассчитывает Score.
Он получает итоговые дельты, вклад каждой меры после лага (отдельно от финальных
изменений), стоимость, остаток бюджета, сроки и синергии. Исходные эффекты каталога
до лага не передаются как итоговые изменения.

Ответ модели запрашивается по JSON-схеме: три коротких качественных комментария.
Числовые факты приложение подставляет из расчёта. Некорректный формат, цифры внутри
комментария, явное ложное заявление об отсутствии переданных стоимости/лагов,
пустой или оборванный ответ приводят к подписанному резервному объяснению.
Эта проверка ограничивает ошибки, но не доказывает истинность любой свободной
формулировки AI; содержание всё равно нужно проверять при демонстрации.

Синергия уже входит в итоговую дельту показателя: например, **B1 +12.5 в Нуре**
включает бонус **+2**. Повторно прибавлять его нельзя. Округление выполняется только
при отображении; движок хранит полную точность.

Симулятор показывает результат формальной модели на основе данных задания. Он не является реальным прогнозом развития Астаны и не заменяет экономическую, инженерную или общественную экспертизу.
